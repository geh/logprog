# Applications of Propositional SAT

*Logical Programming --- Part 3*

## 1. Improvements to DPLL

During the 2000s, DPLL-based implementations improved substantially
through algorithmic optimizations and careful engineering.

-   **Conflict-Driven Clause Learning (CDCL):** when a conflict is
    found, analyze which assignments caused it and add relevant learned
    clauses to the formula.
-   **Backjumping:** skip multiple recursive levels when the conflict
    shows that intermediate levels need not be explored.
-   **Variable-selection heuristics:** choose the next variable
    strategically.
-   **Watched literals:** a technique introduced in 2001 to improve
    Boolean Constraint Propagation (BCP) with little memory overhead.

## 2. A short history of DPLL

    Year System or milestone                              Scale
  ------ ------------------------------- ----------------------
    1960 Davis-Putnam (DP)                         10 variables
    1962 Davis-Logemann-Loveland (DLL)             10 variables
    1986 BDD                                      100 variables
    1996 Stalmarck                              1,000 variables
    1996 SATO                                   1,000 variables
    1996 GRASP                                  1,000 variables
    2001 Chaff                                 10,000 variables
    2003 MiniSAT                              100,000 variables
    2010 . . .                            Millions of variables

The original DPLL method was incomplete for first-order-logic
satisfiability. The 1960 paper had memory problems, and the 1962
paper introduced depth-first search with backtracking.
Breakthrough systems in the late 1990s and early 2000s
helped make DPLL efficient.

## 3. Why did SAT solvers improve so much?

-   Increasing industrial demand.
-   Annual SAT solver competitions.
-   Open-source SAT solvers participating in competitions.
-   Benchmark collections containing:
    -   Random formulas.
    -   Hand-crafted formulas.
    -   Industrial formulas, including hardware, planning, and
        bioinformatics problems.
-   A common input format: DIMACS CNF.

## 4. DIMACS CNF format

Example input:

``` text
c start with comments
c
p cnf 5 3
1 -5 4 0
-1 5 3 4 0
-3 -4 0
```

Format rules:

-   Lines beginning with `c` are comments.
-   The problem line is `p cnf nbvar nbclauses`.
-   Variables are numbered starting at `1`.
-   Each clause is a sequence of nonzero integers, where the sign
    indicates polarity.
-   Each clause ends with `0` on the same line.
-   The variable indices must be within the declared range.

The example declares 5 variables and 3 clauses:

``` text
(1 | !5 | 4)
(!1 | 5 | 3 | 4)
(!3 | !4)
```

## 5. Example SAT solver: MiniSat

Installation and usage:

``` sh
apt install minisat
minisat INPUT [OUTPUT]
```

-   `INPUT` is a file in DIMACS CNF format.
-   `OUTPUT` contains either:
    -   `UNSAT`, or
    -   `SAT` together with a satisfying interpretation.

## 6. Application: Bounded Model Checking (BMC)

Given a system and a property, **Bounded Model Checking (BMC)** checks
whether the property holds for all executions of the system within at
most `k` steps, for all inputs of size at most `n`.

-   Testing checks a small number of executions, which may be of
    arbitrary size.
-   Verification aims to check all executions of every size.
-   BMC checks all executions within a bounded size.

Let us see an example is to understand the general approach rather
than every encoding detail.

## 7. BMC example: the Zune bug

The following function is supposed to convert a day count into a year:

``` c
int daysToYear(int days) {
    int year = 1980;
    while (days > 365) {
        if (isLeapYear(year)) {
            if (days > 366) {
                days -= 366;
                year += 1;
            }
        } else {
            days -= 365;
            year += 1;
        }
    }
    return year;
}
```

This code is the infamous Zune bug: on December 31, 2008,
first-generation Microsoft Zune players became unresponsive.

The defect is an infinite loop on the last day of a leap year. When
`isLeapYear(year)` is true and `days == 366`, the nested condition
`days > 366` is false. Neither `days` nor `year` changes, so the loop
repeats forever.

## 8. State a safety property

Add a variable recording the previous day count and assert that the
count decreases during each loop iteration:

``` c
int daysToYear(int days) {
    int year = 1980;
    while (days > 365) {
        int oldDays = days;
        if (isLeapYear(year)) {
            if (days > 366) {
                days -= 366;
                year += 1;
            }
        } else {
            days -= 365;
            year += 1;
        }
        assert days < oldDays;
    }
    return year;
}
```

Desired safety property: the value of `days` decreases in every loop
iteration.

## 9. BMC step 1 of 4: finitizing loops and inlining calls

Unwind each loop `k` times (here we use `k = 1` as an example) and
add an unwinding assertion after each unrolled iteration.

``` text
Original loop
    |
    v
Unroll the loop k times
    |
    +--> Keep the program assertions
    |
    +--> Add an unwinding assertion
```

For the example, the unrolled code includes an assertion that the loop
condition is no longer true after the bounded iteration:

``` c
if (days > 365) {
    int oldDays = days;
    if (isLeapYear(year)) {
        if (days > 366) {
            days -= 366;
            year += 1;
        }
    } else {
        days -= 365;
        year += 1;
    }
    assert days < oldDays;
    assert days <= 365;
}
```

Interpretation:

-   If a counterexample (CEX) violates a program assertion, a buggy
    behavior of length at most `k` has been found.
-   If a CEX violates only an unwinding assertion, no buggy behavior of
    length at most `k` was found, but a longer one may exist.
-   If there is no counterexample, the program is correct for the
    examined bound `k`.

## 10. BMC step 2 of 4: eliminate side effects using SSA

Convert the program to **Static Single Assignment (SSA)** form:

-   Replace each assignment to a variable `v` with a definition of a
    fresh version `v_i`.
-   Change each use so it refers to the appropriate version.
-   Make conditional dependencies explicit using guarded expressions or
    `ite` nodes.

For example, a conditional update can be represented as:

``` text
days2 = ite(g1 & g2, days1, days0)
year2 = ite(g1 & g2, year1, year0)
```

Here `ite(condition, a, b)` means "if condition is true, choose `a`;
otherwise choose `b`."

A more complete sketch of the versioned variables is:

``` text
days0, year0
   |
   +-- g0 = (days0 > 365)
   +-- oldDays0 = days0
   +-- g1 = isLeapYear(year0)
   +-- g2 = (days0 > 366)
   |
   +-- days1 = days0 - 366
   +-- year1 = year0 + 1
   +-- days2 = ite(g1 & g2, days1, days0)
   +-- year2 = ite(g1 & g2, year1, year0)
   +-- days3 = days0 - 365
   +-- year3 = year0 + 1
   +-- days4 = ite(g1, days2, days3)
   +-- year4 = ite(g1, year2, year3)
```

The assertions are then expressed over the final versions, for example
`days4 < oldDays0` and `days4 <= 365`.

## 11. BMC step 3 of 4: convert the program to equations

Represent the program as a conjunction of equations and assertions:

``` text
year0 = 1980
g0 = (days0 > 365)
oldDays0 = days0
g1 = isLeapYear(year0)
g2 = (days0 > 366)
days1 = days0 - 366
year1 = year0 + 1
days2 = ite(g1 & g2, days1, days0)
year2 = ite(g1 & g2, year1, year0)
days3 = days0 - 365
year3 = year0 + 1
days4 = ite(g1, days2, days3)
year4 = ite(g1, year2, year3)
!(days4 < oldDays0) | !(days4 <= 365)
```

A solution to these equations is a sound counterexample if it represents
an execution satisfying the program semantics for up to `k` unwindings
while violating at least one assertion.

## 12. BMC step 4 of 4: convert equations to CNF

The final encoding translates the equations into a Boolean formula in
CNF. We use a bit-level encoding of an arithmetic assignment such as:

``` text
year1 = year0 + 1
```

At a high level, bit-vector variables are represented by Boolean
variables, and constraints connect input bits, output bits, and the
clauses describing the operation.

``` text
Program equations
       |
       v
Boolean / bit-vector constraints
       |
       v
CNF formula
       |
       v
SAT solver
```

## 13. Final step: run the SAT solver

Give the CNF formula to a SAT solver.

  -----------------------------------------------------------------------
  Solver result                       Interpretation
  ----------------------------------- -----------------------------------
  `UNSAT`                             No assertion violation exists
                                      within the examined bound.

  `SAT`                               There is an execution that violates
                                      an assertion; decode the satisfying
                                      assignment to reconstruct the
                                      counterexample (CEX).
  -----------------------------------------------------------------------

For the Zune example, the counterexample can include `days = 366` in a
leap year, showing why the loop can fail to make progress.
